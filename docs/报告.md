## 1. 项目概述

本项目实现 ToyC 语言(一个面向教学设计的 C 语言简化子集)的编译器,将 ToyC 源程序编译为可在 RARS 模拟器上执行的 RISC-V32 汇编代码。编译器从标准输入读取源码、向标准输出写入汇编,`-opt` 参数开启优化。

编译流水线:

```
源码(stdin) → 词法分析 → 语法分析(AST)→ 语义分析(带注解 AST)
           → 三地址码 IR → 优化(-opt)→ RISC-V32 汇编(stdout)
```

每个阶段都有独立的调试输出(`--dump-tokens` / `--dump-ast` / `--dump-ir`),便于验证与报告展示。

## 2. 词法分析

手写词法器(`src/lexer.h/.cpp`),基于确定性有限自动机,逐字符扫描并维护行号列号,支持:

- 标识符:`[_A-Za-z][_A-Za-z0-9]*`,关键字用哈希表查表识别
- 整数:`0|[1-9][0-9]*`,超长数字饱和处理(合法测试不会出现)
- 注释:`//` 行注释与 `/* */` 块注释(多行注释内换行正确计入行号),未闭合块注释报错
- 所有运算符与标点,含 `&&`、`||`、`<=` 等双字符运算符

### 难点:负数字面量的二义性

语言定义中 NUMBER 的正则为 `-?(0|[1-9][0-9]*)` 含可选负号,但 ToyC 源文件必须能被 C 编译器直接编译,因此 `1-2` 必须是合法的减法。若词法器按正则贪婪地把负号并入数字,`1-2` 会被切成 `NUMBER(1) NUMBER(-2)` 两个相邻字面量,导致语法错误。

**解决方案(与 C 一致)**:词法器始终把 `-` 作为 MINUS 运算符产出,NUMBER 只匹配非负十进制整数;一元负号由语法分析在 `UnaryExpr → "-" UnaryExpr` 层处理。`1-2`、`1--2`、`5*-2` 均自然解析为正确的表达式结构,与 C 语义完全一致,无需任何上下文特判。

配套处理:`-2147483648`(INT_MIN 的字面量写法)——字面量 `2147483648` 超出 int32,仅当它是一元负号的直接操作数时放行,常量折叠在 int64 域计算后按 int32 截断(C++20 定义良好的补码截断),结果落在合法范围内即接受。测试用例 `negative.tc` 覆盖了全部这些边界。

## 3. 语法分析

手写递归下降解析器(`src/parser.h/.cpp`),每个文法产生式对应一个解析函数,结构与课程文法一一对照。文法经检查为 LL(1):`int` 后跟标识符时,通过直接索引 token 数组区分变量声明(`=` 跟随)与函数定义(`(` 跟随)。左递归的 `LOrExpr/LAndExpr/RelExpr/AddExpr/MulExpr` 改写为循环,天然保证左结合;`UnaryExpr` 右递归;if-else 的悬空问题由"else 匹配最近 if"的递归结构自然解决。

AST(`src/ast.h/.cpp`)采用继承体系 + `unique_ptr` 所有权,节点保留行号用于报错;语义分析完成后回填符号指针与常量值,`--dump-ast` 输出带注解的语法树(报告素材)。

## 4. 语义分析

(`src/sema.h/.cpp`)主要工作:

- **符号表**:作用域栈(全局一层 + 每个 Block 一层),内层同名声明自然遮蔽外层;初始化表达式求值完成后才插入符号,`int x = x;` 自然报错;函数符号在分析函数体**之前**插入,支持递归
- **先声明后使用**:名字查找失败即报错,天然实现"使用必须在声明之后"
- **类型规则**:void 函数调用出现在值上下文(条件、赋值右值、运算操作数、实参、return 值)时精确报错;int 函数裸 return、void 函数带值 return 均报错;const 作赋值左值报错;break/continue 通过循环深度计数检查
- **const 编译期求值**:递归求值器,支持字面量、已声明常量及其算术/逻辑组合;**&& / || 严格按短路语义求值**(右侧不参与时不求值,保证 `0 && (1/0)` 这类程序正确);除法按 C 语义向零截断,除数为 0 报错
- **全路径 return 检查**:保守算法(含 `while(常量非零)` 且无 break 的判定),只以**警告**形式报告——该检查在算法上不可能完全精确,若误报为错误会拒绝合法程序;警告级别保证了评测输入的合法程序永远通过

## 5. 中间表示:三地址码

(`src/ir.h/.cpp`)线性指令序列 + 无限虚拟寄存器 + 标签。关键设计:

- **局部变量直接提升为虚拟寄存器**(ToyC 无指针、无取地址,地址绝不逃逸,提升安全)——这是寄存器分配优化的前提;全局变量通过 LOADGLOBAL/STOREGLOBAL 显式访问;**const 引用直接物化为编译期常量**,不占任何存储
- **短路求值在 IR 构建期降级为条件跳转结构**,四种方向组合(`cf/ct × &&/||`)按短路语义精确展开,不物化中间布尔值;`&&`/`||` 作为值使用时再物化 0/1
- 函数调用:CALL 指令携带实参 vreg 列表;被调函数入口用 ARG 指令拷贝形参(前 8 个寄存器、其余经调用者出参区,标准 RV32 ABI)
- 全局变量无静态初值(初始化表达式不可编译期求值)时,在 main 入口按声明顺序生成运行时初始化代码

## 6. 目标代码生成

(`src/codegen.h/.cpp`)RISC-V32 汇编,输出约定集中在 `CodeGenOptions`(伪指令开关、M 扩展开关、main 退出方式),便于按评测环境调整。

- **帧布局**:出参区(仅调用者写入)+ vreg 栈槽/溢出槽 + 保存的 ra/s0/被使用的 s 寄存器;16 字节对齐
- **main 退出码**:实测验证 RARS 的约定——`li a7, 93; ecall`(exit2,新编号)使 a0 成为进程退出码;main 的 return 路径统一跳到公共尾声执行该序列(不 ret 回调用者,避免 ra=0 指令加载错误)。RARS **不支持** `%lo(sym)(reg)` 寻址,全局变量访问统一用 `la` 伪指令
- **O0 朴素模式**:每个 vreg 一个栈槽,指令 = 取操作数 → 运算 → 存回,正确性优先
- **优化模式三操作数直发**:RISC-V 是三操作数指令,操作数在寄存器时直接在目标寄存器上运算(如 `slt t4, t3, s1`),只有溢出操作数才经 t0/t1 加载,消除栈式代码的 mv 往返
- **叶子函数优化**:无 CALL 的函数免存 ra/s0、免设帧指针

## 7. 优化(-opt)

(`src/opt.h/.cpp`)各遍在 IR 上迭代至不动点:

| 优化遍 | 说明 |
|---|---|
| 不可达代码删除 | JUMP/RETURN 之后到下一标签之前的指令;跳转到下一条指令的 JUMP;未引用标签 |
| 常量折叠 + 常量/拷贝传播 | 顺扫维护常量表与 MOV 别名链(重定义时失效),到达标签清空(保守);**算术折叠严格按 int32 回绕语义**(与 RV32 指令行为一致);条件跳转遇常量直接改写/消除;单常量加减转 ADDK/SUBK 直发 addi |
| 强度削减 | 乘 2^k → 移位;乘 0/1、除 1、模 1 特化。**除以 2^k 的移位修正序列在 RV32IM 上不采用**——div/rem 本身已是单指令,4 条指令的修正序列反而更慢(报告了该取舍) |
| 死代码删除 | 基本块划分 + CFG + 精确活跃性分析(不动点迭代),删除死定义;调用返回值死时保留调用副作用、丢弃结果 |
| 比较-分支融合 | `cmp` 结果仅被紧随的分支使用时,合并为单条真实分支指令(如 `LE+BRZ → blt y,x`),消灭 slt/xori/beqz 三连 |
| 频率寄存器分配 | 见下 |

### 频率寄存器分配器

每个物理寄存器至多分配给一个 vreg(无区间重叠判定,构造上保证正确):

- 跨调用存活的 vreg(定义与最后使用之间存在 CALL)→ s1-s11(被调用者保存)
- 不跨调用的 vreg → t3-t6 与 a0-a7
- **形参 vreg 禁止进入 a0-a7**(序言逐条拷贝 ARG 时写入 a 寄存器会覆盖尚未拷贝的实参——回归测试 args.tc 抓出的真实 bug)
- **实参直通**:只被某次 call 使用一次且定义紧邻该 call 的 vreg 直接分配到对应实参寄存器,定义指令直接写 a_i、调用时零搬运
- 按定义+使用频率降序分配,分配不到的溢出到栈槽;仅保存实际使用的 s 寄存器

## 8. 测试与验证

- **差分测试(核心方法)**:ToyC 源文件是合法 C 子集——同一份源码分别用本编译器(O0 与 -opt 两个路径)编译并在 RARS 运行,再用 MSVC `cl.exe /O2` 原生编译运行,三方退出码必须一致。12 个用例全部通过
- 测试用例覆盖:全局常量/变量、递归、短路求值(含被保护的除零)、break/continue、嵌套作用域遮蔽、负数边界(`1-2`、`1--2`、INT_MIN)、超过 8 个参数的调用(栈传参)、void 函数、嵌套循环、运行时全局初始化(ToyC 扩展语义,单独目录 RARS 直测)
- 语义分析另有 6 个错误用例(未声明标识符、const 赋值、void 作右值、循环外 break、const 非常量初始化、声明前调用),验证诊断准确
- 性能测试以 RARS `ic` 输出的动态指令数为机器无关的确定性指标

### 踩坑记录(部分)

1. **MSVC 编码**:源码含 UTF-8 中文注释时,MSVC 默认按本地代码页(GBK)解码会静默破坏解析——本编译器构建加 `/utf-8`;差分测试的 cl 调用同样必须加 `/utf-8`(logic.tc 曾因此得到错误参考值)
2. **bat 脚本编码**:cmd 按本地代码页解析 .bat 文件,UTF-8 中文注释可能吞掉换行导致命令行失效——bat 一律 ASCII
3. **RARS 约定**:`a7=17` 的 exit2 编号无效(掉出代码底部),新编号 93 才传播退出码;main 直接 ret 会触发指令加载错误(ra=0)
4. **寄存器分配双分配**:形参与临时值曾同时分到 t3(12 参数用例暴露)——分配池互不相交是正确性根基
5. **强度削减方向**:除数 2^k 的移位序列(带符号修正)在带 M 扩展的机器上是负优化,已移除并记录理由

## 9. 总结与展望

本编译器完整实现了 ToyC 到 RISC-V32 的全部编译流程,功能测试全部通过,优化后三个性能基准的动态指令数分别减少 17%/62%/67%。可扩展方向:图着色寄存器分配、公共子表达式消除(GVN)、循环不变量外提、函数内联。
