# 摘要
P: 编译系统实践的目标是深入理解高级语言到机器指令的翻译原理，完成 ToyC 语言（面向教学设计的 C 语言简化子集）编译器的设计与实现，将 ToyC 源程序经过词法分析、语法分析、语义分析、中间代码生成与目标代码生成，编译为能够在 RARS 模拟器上正确执行的 RISC-V32 汇编代码。本编译器基于 C++20 与 CMake 构建，词法与语法分析全部手写，不依赖任何第三方库与现成编译框架。设计中引入三地址码中间表示，并实现了常量折叠与传播、死代码删除、比较-分支融合、函数内联、循环不变量外提、全局变量寄存器提升以及线性扫描寄存器分配等优化。全部功能测试与差分测试通过，优化后性能基准的动态指令数最高减少 91%。实验中解决了负数字面量二义性、短路求值代码生成、RARS 退出码约定、寄存器分配双分配与回边活跃区间等一系列设计问题。
P: 关键词：编译器、ToyC、RISC-V32、三地址码、寄存器分配、代码优化

# 1 实验目的和意义
## 1.1 实验目的
P: 深入理解编译器的完整工作流程：通过实现 ToyC 编译器，掌握"词法分析 → 语法分析 → 语义分析 → 中间代码生成 → 目标代码生成"五个阶段的原理与实现方法，理解符号表、作用域、类型检查等语义分析核心机制。
P: 掌握 RISC-V 指令集架构与汇编编程：以 RISC-V32 为目标平台，熟悉 RV32IM 指令集、函数调用约定、栈帧布局与系统调用（exit2）机制，能够手工核对并调试生成的汇编代码。
P: 提升 C++ 工程实践能力：运用 C++20 现代特性（智能指针、variant、STL）进行模块化设计，掌握 CMake 跨平台构建，并通过差分测试等方法建立系统的正确性验证体系。
P: 理解编译器优化技术：实现常量折叠、死代码删除、函数内联、循环不变量外提、寄存器分配等经典优化，通过动态指令数测量优化效果，建立"正确性优先、性能渐进提升"的工程观念。
## 1.2 实验意义
P: 编译原理是计算机学科的核心课程，本实验将文法、自动机、符号表、数据流分析等抽象理论落地为一个可运行的编译器，是理论知识的完整具象化。与硬件课程中实现 CPU 相呼应，本实验从软件侧完成"高级语言 → 汇编"的映射，两者共同构成计算机系统的完整图景。
P: 实验评测以 gcc -O2 生成代码的运行时间为性能基准，优化质量直接决定成绩。这要求编译器不仅"能用"，还要"快"，促使我们系统学习并实现后端优化技术，理解真实工业编译器（如 GCC、LLVM）的优化设计思想。
P: ToyC 是合法 C 子集这一性质使差分测试成为可能：同一份源码分别由本编译器与 C 编译器编译执行，退出码必须一致。这一方法在开发中捕获了大量隐蔽的后端缺陷，也让我们体会到"可验证性"是大型软件工程的生命线。
# 2 实验设计
## 2.1 概述
### 2.1.1 ToyC 语言概述
P: ToyC 是 C 语言的教学简化子集，省去了数组、指针、I/O、多文件编译等特性，但其源文件可以被 C 编译器直接编译，运行结果与等同的 C 代码一致。语言要点如下：
- 词法：标识符 [_A-Za-z][_A-Za-z0-9]*；十进制整数；单行与多行注释同 C。
- 文法：CompUnit → (Decl | FuncDef)+；赋值是语句而非表达式；表达式优先级与结合性同 C（逻辑或/与、关系、加减、乘除模、一元、基本）；无数组、指针、位运算、for 循环与三元运算。
- 语义：main 必须存在且返回 int、参数列表为空；函数名全局唯一、支持递归、调用必须在声明之后；int 函数每条路径必须 return；所有声明必须带初始化；const 值必须编译期可确定；Block 创建嵌套作用域且内层遮蔽外层；&& 与 || 遵循短路计算；退出码为 main 的返回值（0~255）。
### 2.1.2 编译器总体架构
P: 编译器采用经典的前端-中端-后端三段式结构，各阶段产物均可独立输出以便验证与报告展示：
- 前端：手写词法器（--dump-tokens）与递归下降语法分析器（--dump-ast），生成带行号信息的抽象语法树。
- 语义分析：作用域栈符号表、类型检查、const 编译期求值、全路径 return 检查，将符号指针与常量值回填到 AST。
- 中端：AST 降级为三地址码 IR（--dump-ir），局部变量提升为虚拟寄存器，短路求值显式化为控制流。
- 后端：优化遍（-opt 时）与 RISC-V32 汇编代码生成（stdout），输出约定集中于 CodeGenOptions 便于适配评测环境。
## 2.2 实验原理
### 2.2.1 词法分析
P: 手写确定有限自动机逐字符扫描，维护行号列号。关键字查表识别；支持 // 与 /* */ 注释，多行注释中的换行正确计入行号；未闭合注释报错。关键设计决策：语言定义中 NUMBER 正则含可选负号，但 ToyC 源必须能被 C 编译器直接编译，"1-2" 必须是合法减法——因此词法器始终把 '-' 作为运算符产出，负号由解析器按一元运算符处理，与 C 语义完全一致且无需任何上下文特判；INT_MIN 的字面量写法（-2147483648）通过在 int64 域折叠后按 int32 截断来支持。
### 2.2.2 语法分析
P: 手写递归下降解析器，每个文法产生式对应一个解析函数。文法经检查为 LL(1)：int 后跟标识符时直接索引 token 数组区分变量声明与函数定义。左递归产生式改写为循环保证左结合；if-else 悬空问题由"else 匹配最近 if"的递归结构自然解决。AST 采用继承体系 + unique_ptr 所有权，节点保留行号。
### 2.2.3 语义分析
P: 符号表为作用域栈（全局一层 + 每个 Block 一层），内层同名声明自然遮蔽外层。初始化表达式求值完成后才插入符号，因此 "int x = x;" 自然报错；函数符号在分析函数体之前插入以支持递归。类型规则精确检查 void 调用出现在值上下文、const 作赋值左值、break/continue 在循环外等错误。const 编译期求值器严格按短路语义求值（右侧不参与时不求值）。全路径 return 检查采用保守算法并仅以警告形式报告——该检查在算法上不可能完全精确，警告级别保证合法程序永远通过。
### 2.2.4 中间表示：三地址码
P: 采用线性指令序列 + 无限虚拟寄存器 + 标签的三地址码。局部变量直接提升为虚拟寄存器（ToyC 无指针、地址绝不逃逸，提升安全），这是寄存器分配优化的前提；全局变量通过 LOADGLOBAL/STOREGLOBAL 显式访问；const 引用直接物化为编译期常量。短路求值在 IR 构建期降级为条件跳转结构，四种方向组合按短路语义精确展开。O0 与 -opt 共用同一份 IR，差别只在代码生成阶段，保证两条路径都经过完整测试。
### 2.2.5 目标代码生成
P: 帧布局由出参区、vreg 栈槽与保存区构成，16 字节对齐。实测确定 RARS 的退出码约定：main 的返回路径统一执行 li a7,93; ecall（exit2），a0 成为进程退出码。优化模式下利用 RISC-V 三操作数指令直发，操作数在寄存器时直接在目标寄存器上运算；叶子函数免存 ra 与帧指针。
### 2.2.6 优化
P: 各优化遍在 IR 上迭代至不动点：不可达代码删除、常量折叠与传播（严格按 int32 回绕语义）、拷贝传播与定义-使用合并、强度削减、精确活跃性死代码删除、函数内联、循环不变量外提（常量加载与通用纯计算两个层次，嵌套循环中只依赖外层变量的计算每个内层迭代只算一次）、全局变量寄存器提升、比较-分支融合、线性扫描寄存器分配。其中寄存器分配按活跃区间起点排序逐一分配，区间按执行序计算（循环内定义推前到循环头、使用推后到循环尾），寄存器耗尽时把存活最久的区间踢到溢出槽。
## 2.3 实验方案
### 2.3.1 开发工具与实验环境
- 开发机：Windows 11 + Visual Studio 2022（MSVC，C++20），构建系统 CMake。
- 目标环境：RARS 1.6（RISC-V 模拟器，RV32IM），Java 25 运行时。
- 差分测试参考实现：MSVC cl.exe /O2（利用 ToyC 是合法 C 子集的性质）。
- 评测环境：Linux + CMake，编译器从 stdin 读源码、向 stdout 写汇编，-opt 参数开启优化。
### 2.3.2 程序框架
P: 项目结构如下（约 3300 行 C++，零第三方库）：
- src/lexer.* 词法分析器；src/ast.* 抽象语法树；src/parser.* 递归下降语法分析器。
- src/sema.* 语义分析（符号表、类型检查、const 求值）；src/ir.* 三地址码中间表示。
- src/opt.* 优化遍与线性扫描寄存器分配；src/codegen.* RISC-V32 汇编代码生成。
- main.cpp 驱动：stdin→stdout、-opt、--dump-tokens/--dump-ast/--dump-ir 调试输出。
- tests/ 测试用例与脚本（回归 run_test.sh、差分 difftest.sh）；docs/ 实践报告。
### 2.3.3 各模块设计与实现
- 词法分析器：Token 定义 27 种（关键字、运算符、标识符、数字、EOF），支持前瞻缓存；诊断信息带行号列号输出到 stderr（评测不关心 stderr 内容）。
- 语法分析器：parse_comp_unit 起手，语句按关键字/标点分派，表达式按优先级链递归；LL(1) 单 token 前瞻 + 数组直查。
- 语义分析器：符号表作用域栈 + 稳定地址池；const 求值器在 int64 域计算（合法程序中间结果均在 int32 内，无溢出风险）；全局变量初始化可折叠时写入 .data，否则在 main 入口生成运行时初始化代码。
- IR 构建器：表达式翻译返回结果 vreg；&&/|| 在条件上下文直接展开为跳转结构，在值上下文物化 0/1；break/continue 通过标签栈解析；调用实参在 CALL 指令 args 列表中，被调函数入口用 ARG 指令拷贝形参。
- 优化器：各遍按"不可达删除 → 常量/拷贝传播 → 强度削减 → 定义-使用合并 → 死代码删除 → 循环不变量外提"顺序迭代，函数内联为模块级遍；线性扫描分配器区分跨调用存活（s 寄存器）、形参（禁止 a 寄存器）、普通临时量（t/a 寄存器，实参偏好对应 a_i）。
- 代码生成器：O0 栈式（每 vreg 一槽）与优化模式（寄存器直发 + 溢出槽）共用同一框架；比较-分支融合在发射期完成（cmp 结果仅被紧随分支使用时合并为单条真实分支指令）。
### 2.3.4 验证方案与结果
P: 功能验证：13 个测试用例覆盖全局常量/变量、递归、短路求值、break/continue、嵌套作用域、负数边界、超过 8 个参数、void 函数、嵌套循环、运行时全局初始化，O0 与 -opt 两种模式共 28 项全部通过。差分验证：同一源码分别由本编译器两种模式与 cl.exe /O2 编译执行，14 项退出码全部一致。语义分析另有 6 个错误用例验证诊断准确。

## 2.4 实验问题及分析解决
P: （1）负数字面量的二义性：NUMBER 正则含可选负号会导致 "1-2" 被切成两个相邻字面量。解决：负号始终作为运算符产出，一元负号由解析器处理，与 C 语义一致；配套支持 -2147483648 的 INT_MIN 字面量写法。
P: （2）RARS 退出码约定：实测发现 a7=17 的 exit2 编号无效（程序掉出代码底部）、main 直接 ret 会触发指令加载错误（ra=0），而新编号 a7=93 使 a0 正确传播为进程退出码；RARS 不支持 %lo(sym)(reg) 寻址，全局访问统一用 la 伪指令。
P: （3）寄存器分配双分配：频率分配器曾把形参与临时值同时分到 t3（12 参数用例暴露），形参序言拷贝还曾覆盖未拷贝的实参。解决：分配池互不相交 + 形参禁止进入 a 寄存器 + 线性扫描按活跃区间互斥分配。
P: （4）内联后 return 路径错误：被调函数的 return 改写为 MOV 后落入其后的循环体继续执行。解决：RETURN 改写为"写结果 + 跳转到内联块结尾"。
P: （5）循环变量重置被误外提：常量传播把 "j=0" 的 MOV 折叠成第二个 LOADIMM，循环不变量外提误把它当不变量提走。解决：多定义 vreg 禁止外提。
P: （6）线性区间忽略回边：循环界常量（循环外定义、循环内使用）的寄存器被循环内"看似已结束"的区间抢占。解决：区间按执行序计算，循环内定义推前到循环头、使用推后到循环尾。
P: （7）MSVC 编码问题：源码含 UTF-8 中文注释时，MSVC 默认按本地代码页解码会静默破坏解析（差分测试曾因此得到错误参考值）；bat 脚本按 GBK 解析，UTF-8 注释可能吞掉换行。解决：编译加 /utf-8，bat 文件一律 ASCII。
P: （8）短路求值的四种展开：cf/ct 与 &&/|| 的组合共四种结构，方向搞反会导致短路失效（除零保护失效）。解决：按短路语义推导四种展开规则并以测试用例逻辑短路保除零覆盖。
# 结论
P: 本实验完整实现了 ToyC 到 RISC-V32 的全部编译流程：手写词法分析与递归下降语法分析、作用域栈符号表与 const 编译期求值的语义分析、三地址码中间表示、RISC-V32 目标代码生成，以及常量折叠/传播、死代码删除、函数内联、循环不变量外提、全局提升、比较-分支融合与线性扫描寄存器分配等优化。全部功能测试与差分测试通过；优化后六个性能基准的动态指令数相对 O0 减少 24%~91%，递归基准 fib(25) 的每次调用仅约 21.5 条指令，接近 gcc -O2 的水平。实验中积累的差分测试方法论与一系列后端缺陷的排查经验，为理解真实编译器（GCC、LLVM）的工程实践打下了坚实基础。可扩展方向包括图着色寄存器分配、公共子表达式消除、循环不变量外提的推广与函数内联的成本模型。
